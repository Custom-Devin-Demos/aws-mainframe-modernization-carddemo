# CBACT02C parity fixtures

Every `expected/` file below comes from the COBOL program's logic, never from the Java job. "GnuCOBOL"
means: generated by `tools/cobol/run.sh`, which runs the unmodified `app/cbl/CBACT02C.cbl` under GnuCOBOL
3.1.2 against an indexed CARDFILE built by `LOADCARD.cbl`, then converts SYSOUT with `to_canonical.py`.

Canonical form: `sysout.csv` = `line_no,line_text`, each DISPLAY line right-trimmed; `card_listing.csv` =
the six CVACT02Y columns (FILLER dropped), PIC X right-trimmed, PIC 9 kept as raw characters (they are
`STRING` columns, see `schemas/card_listing.schema.json`), RFC 4180 quoting where needed.

| Scenario | Input | Expected | Derivation | Rules |
|----------|-------|----------|------------|-------|
| `sample-data` | `app/data/ASCII/carddata.txt` (50 cards, via `SampleData.file`) | `card_listing.csv`, `sysout.csv` | GnuCOBOL | 01-05, 07, 08 |
| `key-order` | 7 cards in reverse/shuffled order, incl. short key `4111` (space-padded) and `9999999999999999` | `card_listing.csv`, `sysout.csv` | GnuCOBOL (the BDB browse returns key order) | 03 |
| `unload-format` | CRLF line ends, stripped trailing blanks, blank / whitespace-only lines, no final newline | `card_listing.csv`, `sysout.csv` | GnuCOBOL (LOADCARD applies the same unload rules as `FixedWidthFile`) | 11 |
| `raw-content` | leading spaces, `,` and `"` in names, blank and non-numeric PIC 9 bytes, lower-case status, non-blank FILLER | `card_listing.csv`, `sysout.csv` | GnuCOBOL | 04 |
| `empty-file` | zero-byte unload | `card_listing.csv` (header only), `sysout.csv` | GnuCOBOL (first READ → status 10) | 06 |
| `missing-file` | none (no CARDFILE) | `sysout.txt` | GnuCOBOL (OPEN → status 35, `CEE3ABD` shim RC 99) | 02, 09, 10 |
| `malformed-overlength` | record 2 is 151 bytes | `sysout.txt` | **Hand-derived**: such an unload cannot be REPROed into a `RECORDSIZE(150 150)` KSDS, so the Java job reports OPEN status 39; lines follow `0000-CARDFILE-OPEN` + `9910` + `9999` | 02, 09, 10 |
| `malformed-duplicate-key` | record 3 repeats record 1's key | `sysout.txt` | **Hand-derived**, as above (a KSDS cannot hold duplicate primary keys) | 02, 09, 10 |
| `malformed-non-ascii` | UTF-8 `é` in a name | `sysout.txt` | **Hand-derived**, as above (not legacy ASCII) | 02, 09, 10 |
| `io-status` | 21 file statuses | `ascii.csv` | GnuCOBOL: `9910-DISPLAY-IO-STATUS` extracted verbatim and driven by `IOSTAT.cbl` | 09 |
| `io-status` | same | `ebcdic.csv` | Independent script `ebcdic_io_status.py` (Python cp037 codec), applying the 9910 rule with EBCDIC code points as on z/OS | 09 |

Not file fixtures: READ statuses other than 00/10 and CLOSE errors cannot occur with an in-memory KSDS,
so `FileStatusBranchesTest` injects them through `CardFile`; its expected lines are hand-derived from
`1000-CARDFILE-GET-NEXT` / `9000-CARDFILE-CLOSE` and the `io-status` tables.

Regenerate with `tools/cobol/run.sh`; the hand-derived `sysout.txt` files are not touched by it.
